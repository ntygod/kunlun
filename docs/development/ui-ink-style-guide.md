# 《昆仑》画面与界面风格规范 · 墨色山水 / 绢纸江湖

日期：2026-10-22。实施分支：`feat/ui-ink-silk-20261022`，PR16。

本规范是 V3 第08模块的实施补充，不改写八个权威策划源。原有地域色板、像素尺寸、固定视角、人物造型与剧情因果仍以 V3 为准。下文区分“本轮已接入的表现代码”“需要继续验收的界面”“尚未制作的成品美术”。

## 1. 风格决定

**写意而非潦草，古典而非繁复，清晰而非手游化。** 世界表现山河与人物，界面表现书卷与行旅。界面不模仿网页仪表盘，不用霓虹、玻璃泛光、夸张圆角、满屏花纹或读字时持续漂移的镜头。

世界保留手工像素；系统界面使用独立高清中文、墨色面板和克制的细金线；对白采用浅纸底深字，让台词与人物行为成为阅读中心。主标题以原创静态矢量山形、月色和留白建立气质。标题剪影是UI装饰，不冒充最终像素地图。

### 颜色与语义

唯一代码入口：`game/scripts/ui/ink_theme.gd`。

| 角色 | 色值 | 使用边界 |
|---|---|---|
| 玄墨底 | `#0B151B` / `#101F25` | 黑边、输入底、卡片，不使用纯黑硬切 |
| 黛青面板 | `#172C32` / `#203A3F` | 菜单、操作区、浮层；不能吞没文字 |
| 绢纸 | `#EEE6D5` | 对白底板，不给所有页面铺黄色旧纸纹理 |
| 主文字 | `#EEE8D9` | 深底上的主要内容；纸底改为玄墨字 |
| 次文字 | `#B4BEB3` | 说明、来源、辅助状态，不替代关键信息 |
| 暗金 | `#D1B478` | 标题、主操作、键盘焦点；不滥用于所有边线 |
| 青玉 | `#8BC0AA` | 正常生命、友方与积极反馈，同时保留数值/标签 |
| 朱砂 | `#DF9B88` | 伤势、破坏性确认；不能只靠红绿传达状态 |

主操作、普通操作、次操作、危险操作和纸面对话按钮分别使用 Theme variation。Hover 与键盘 focus 不混为一谈；禁用按钮仍需能读清。错误反馈不自动消失，沿用原业务反馈规则。

### 字体、留白与窗口

沿用工程内已有中文字体，不新增在线字体或运行依赖。标题、正文、说明分层；正文使用正常字形，不用书法字体排长段。

公共页面在桌面宽窗采用约18px正文、32px页面标题；紧凑窗口约14px正文、23px标题。对白桌面20px、紧凑14px。已有章节紧凑战斗与机关的局部字号暂保留，以免同时改变解谜坐标和密集操作；它们需要逐场实机复验，不能据此声称所有12px文本已经消除。

间距围绕4/8/12/16/24px组织。主标题左右分区；探索提示合并为清晰的目标牌与操作条；菜单通过主次按钮和说明层级表达顺序。长内容必须滚动或换行，不缩字塞满一屏。

## 2. 世界画面制作标准

世界 `SubViewport=320×180`、最近邻整数放大、黑边居中、32×32瓦片、标准人物32×48容器与约24×40可见体态沿用V3。UI不能改变移动、碰撞、相机或世界像素网格。不同屏幕上的汉字不跟随世界像素一起粗暴缩放。

地域色板沿用V3的十套分区：川蜀湿岩与黄泥、江南烟水、华山苍岩、西域风沙等保持差异，不把整部游戏统一染青。统一的是明度层级、材质笔触与人物辨识度，不是所有场景同色。

地图以大形先行：可行走面、危险边界、目标物、前后遮挡明确，再增加瓦片变化和道具。远景降低对比，角色轮廓与互动点保持更高辨识度。雨、雾、烛火和水面是有节奏的少量像素帧，不用屏幕空间模糊掩饰占位资产。最终角色朝向、右衽、佩剑和标志物仍需逐帧校正；不使用AI伪像素、缩小概念图或未经修正的镜像作为终稿。

战斗最终舞台仍依V3的四分之三侧向阵位制作；本轮的状态卡与操作面板不是战斗角色动画、命中特效或场景终稿的替代品。配音、音乐和音效本轮没有新增。

| 暂停 / 保存 / 读取 / 重开 | 统一面板、强调主操作、危险确认、保存提示 | 仍是手动/自动两槽；不是新增多槽浏览器 |

覆盖指公共显示接入，不代表所有分支画面均已人工验收。第14、15章仍在原草稿分支，本PR不替它们作合并决定；后续合并需解决入口差异并补对应章节截图和实机操作。

## 4. 动效准则与 skill 使用

用户提供 `alchaincyf/huashu-art-motion`，本轮通过GitHub读取了其 `SKILL.md`（版本1.2.0，blob `73f2248675f92a2b1928fa0d35e8369a3ea2292a`）。本地环境网络/DNS不可用，未通过npx安装，也没有声称安装成功。

采用其中“一套色板贯穿”“构图服务内容”“读字时稳定”“用真实帧复核”的方法。它面向艺术动画/视频，而非Godot界面，因此没有导入其Canvas、视频拼接、AI角色、口播或快速运镜门禁。项目原有手工像素纪律优先。

本轮仅在新打开的模态面板使用140ms透明度过渡；不移动按钮、不延迟输入、不为每次战斗刷新重复播放大动画。减少动效立即停止过渡并恢复完全可见。对白正文、回合数字、机关坐标和HUD不做漂移/呼吸/震屏；战斗的世界震动不能带动高清UI。

## 5. 实现边界

`ink_shell.gd` 继承原 `main.gd`，只在表现入口装配样式；`main.tscn` 指向新shell。原状态机、任务、严格重放、成长、存档格式和战斗内核不修改。菜单设置写 `user://ui_preferences.cfg`，不写自然存档。

`ink_journal.gd` 仅读取现有记录与已经获得的技能/物品。显示名称从运行JSON解析，不从冲突的MAP/ACT设计编号自动绑定。未知名称仍保留原始标识，避免胡编道具或武学；未本地化项需另行补映射。

`ink_theme.gd` 是色彩和原生控件主题的单一入口；`ink_backdrop.gd` 为标题装饰；`ink_vitals.gd` 为只读桌面摘要。换肤不能获得战斗指令权限。保留PR15的目标偏好、焦点和过期控件防护。

## 6. 验证与交付门槛

工作流 `.github/workflows/ink-ui.yml` 固定Godot4.6.3，校验官方SHA512，仓库只读权限，测试使用隔离XDG目录。运行数据校验、干净导入、既有基础/章节UI相关测试、新UI检查与启动；检查退出码与引擎诊断，不把exit0的解析错误算成功。

原生X11渲染脚本覆盖640×360和1280×720的标题、探索、对白、选择、暂停、四页记事、设置、校准、教学与战斗图库，保存PNG、窗口边界报告及原始日志。战斗图库有明确的测试快照标注，原生渲染不等于自然键鼠通章。1366×768另做整数缩放与结构检查。

首次 `4d3f3c0` 的导入确实失败：新代码的 `Skin` 常量与Godot原生类型重名，因错误日志门禁被拦截；截图未执行。此记录保留，修复后需重新执行，不沿用旧结果。

后续执行结果以PR记录和对应Actions日志为准。源码存在、主题接入、自动检查、原生截图、视觉审图、自然操作、成品美术和发布导出分别报告。草稿不自动合并。
