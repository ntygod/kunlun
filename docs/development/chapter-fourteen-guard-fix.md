# 第14章金刚护持类型修复

基线 `c0fc4e15945640f799e9411f02ed11f11d260597`，2026-10-21。

HS_A01 初始化先设 `kind=skill`，随后 Dictionary.merge 默认不覆盖，导致 prepare 虽执行但 stance.kind 不是 guard，敌方攻击无法寻找护卫。仅将 HS_A01、HS_A04 的定义合并显式设置 overwrite=true；后者保持既有解控护盾处理，统一 release 类型。没有改伤害公式、资源规则、存档协议或自然存档。

使用现有战斗测试的角色 fixture，在入场前合法换装四槽包含 HS_A01；无战斗状态强改。原版首轮梁萧观势、花生护持梁萧，主持造成梁萧220伤害、无代受；普通 guard_ally 对照梁萧110/花生84。修复后同一合法命令产生梁萧55/花生109、反伤87、协同1。自护不会代受队友；解脱为队友提供护盾，未变为护卫。默认推荐配置不包含 HS_A01，不能将这项模型回归说成 GUI 已验。

实际执行：Godot4.6.3干净导入；新 test_chapter_fourteen_guard.gd 27项通过（含两项独立旧引擎快照）；既有 test_chapter_fourteen_combat.gd 143项通过，31轮胜利。隔离 XDG 为 /tmp/kunlun-hs-guard/{cache,data,config}，日志/原诊断/旧引擎生成的两个 JSON 保留于该目录。新测试独立运行25项；设置 CH14_GUARD_OLD_FIXTURES=/tmp/kunlun-hs-guard 追加旧快照验证。这些临时证据非版本化自然档。

兼容性：旧引擎产生的未结算普通 guard_ally 指令快照在修复后真实严格重放通过；旧引擎已经结算错误 HS_A01 的快照会因结果改变而拒绝。这是明确迁移限制，不偷偷改写旧状态；使用此技能的旧战斗需要从战前安全档重新进入。默认配置未用 A01 的自然路线不受该错误结算差异影响。新引擎 A01、自护和 A04 的未结算与结算后快照均重放通过。
