## 输入与界面的短回归

在640×360和1280×720真实窗口各观察一次主要受控面板。控制栏、当前人物、目标方向、选项全文应可读；不以“矩形在屏幕内”代替像素阅读。鼠标方向按钮和键盘方向各移动一步，选项弹窗可选择并执行；第一下Esc关闭弹窗，未开弹窗时Esc进入系统菜单。

只补本章入口的共性边界，不重复过去各章全部测试：

1. 新进程第一次在可保存受控状态按F5，不先显示“不支持保存”提示预热。确认顶栏约64像素高、完整“上次手动保存”时间和结果；不遮挡大半屏幕。对白/选择F5只显示本次未保存说明，原文件哈希/修改时间不变。下一次正常输入隐藏提示且照常处理。
2. 菜单向下滚动，再返回新的选择/记事/整备内容，标题和首选项回到首屏。同一弹窗跨帧、同一内容刷新保持用户滚动位置。
3. 游戏失焦到其他窗口后，记录桌面焦点状态；普通非定向输入不能推动角色。F5/F9或菜单返回不能自动恢复游戏移动权限；重新聚焦后只有新按键才移动，松键停止。若测试工具把输入强制定向游戏，须单列其真实焦点日志，不能混称普通失焦输入。
4. 柳、花生、晓霜切换后分别确认标题实名和受控人物脚位。至少柳孤舟部分态做一次新PID恢复；不把只检查梁的第一场景当作所有视角通过。
5. 战斗目标显示中文人名，metadata/命令ID仅供诊断，不出现在玩家目标文本中。机关/战斗有合法部分态时按原规则保存；失败反馈必须可见，不允许为了测试放开不安全保存。
