## 2. 明确改变的保证

v4的已完成章摘要验证“声明结果符合已登记剧情的终态约束、选择和奖励依赖”，不证明玩家真的输入过历史每一步。改为另一套自洽的已完成历史可能被接受。这是单机结果一致性的明确边界，不引入本机密钥、签名、账号或外部信任；checksum不冒称真实性证明。

当前未完成章仍从该摘要基线真实重放。旧v1/v2/v3必须先完整通过各自原验证器，不能把坏旧档直接当摘要导入。坏类型、未知字段/章节/技能、重复奖励、未满足分支依赖和当前章越步仍拒绝，失败不替换当前会话。

## 3. 最小格式

顶层固定字段：`version=4`、`active_chapter`、`archive`、`current`。

- `archive`是按章连续的扁平数组，最多21项（序章+1—20章）；实际仅接受已登记且有摘要适配器的章节，目前0—3。没有`prior_campaign`、递归存档或源文本。
- 每项有严格的`chapter`、`summary_version`、本章合法`choices`、必需`milestones`、`boundary_vitals`。序章额外保留有限、登记过的`observed`勘查清单与顺序；第02章额外有有界`optional_commits`与最终`optional_dispositions`。
- `current`仅保存当前未完成章的输入记录、导航、必要的活动战斗检查点；不重复保存可从输入推出的actors/items/XP、机关终盘和完成收据。序章已有简洁状态验证器，沿用其有限当前状态。
- 已完成当前章也归入archive；current仅保留终局导航/界面定位，不继续驻留本章全部点击。active_chapter仍指最后完成章，保留归档界面与继续下一章入口语义。
- 新格式中的派生XP、技能、物品、知识、年龄、角色状态和奖励账由注册规则重建，不接受候选档直接merge的派生字典；额外注入字段即拒绝。

当前章压缩只做无损去重：原始输入保留，删除输入执行必然自动生成的重复complete记录，以及puzzle_records/escape_receipts等可重建副本；B01当前阶段/编排检查点仍严格重放。不会把当前章未完成玩法改为“成功”布尔值。

## 4. 完成摘要适配器

新增独立摘要codec/归约器；每章适配器读取注册规则，应用完成事务及选择效果，不伪造玩家输入、不调用旧战斗/机关控制器、不重新播放旧chronology。共用效果应用可抽为内部归约函数，真实运行的验证入口保持原规则。

摘要检查至少包含：
- 所有必需主线完成里程碑，分支对应项准确，未知/重复/缺失拒绝；十算保留“已见发散”与“主动歇手”，不改写成求得有限解。
- 选择白名单及前置物品依赖；墓碑仍梁文缺靖，剑与断刃不是同一物。
- 第02章XP=1440+400×R01归档+250×K01归档，铜钱250；A01恰2级、A02原级、P01按剧情授予，K01仅未来资格而非A04技能。
- 第03章新增1030XP和300铜；砚唯一换质或保持完整，算盘真实借取/损毁，外衣/信物/药物归属，晓霜猴犬留守而非死亡，梁萧独行。

第02章optional_commits最多4条，保持实际语义提交顺序，各至多一次：r01_puzzle_solved、k01_puzzle_solved、r01_archived、k01_archived。archived必须在该solved之后；solved携带合法选择。最终disposition只允许completed/missed/declined且与提交相符。

这保留合法“机关已解、未聊完收尾便暂停，后来错过”的残留：R01留后页会先产生晓霜持有的第一页，但没有算册/400XP/辅助；K01可留下方法选择而没有札记/250XP/未来资格。反复开关窗口、未完成拼图每个操作、无跨章用途的盘面不继续保存。`state.assists`是奖励能力，不能误当解题assisted而删除。

HP/MP只接受梁萧两个有限整数，按固定成长后缀约束：
- 第01章章末HP至少58、MP至多45，不能只按章末最大217/50放行。
- 第02章HP至少`章末max_hp−256+1`，MP至多57；不同支线终态依赖对应XP成长面板。
- 第03章HP至少`章末max_hp−B01入场max_hp+1`、MP不超过B01入场max_mp，后续剧情伤势照注册效果保留。
- 这些是必要边界，不声称每个数对存在精确历史战斗路径。文靖剧情死亡后现有固定HP520不擅自归零，其他角色不接受自由边界面板。

## 5. 旧格式迁移与原子性

- 保留独立旧版导出/校验函数。旧验证器内部仍用旧结构比较重放结果，不能因默认导出改v4而破坏旧验证。
- 读旧档：临时候选严格旧校验 → 生成摘要 → v4再校验 → 成功后替换内存。失败时原会话不变。
- 不在普通读取时悄悄覆盖磁盘原档。首次实际保存新格式时，先保存待替换槽原始字节为`.v1.bak`/`.v2.bak`/`.v3.bak`；备份写失败不替换原槽，既有备份不覆盖。若读旧手动档后只写auto，原手动档仍原样保留。
- v4临时文件写完/关闭后，同目录原子替换；无效候选不覆盖旧槽。迁移后的下一次v4读取只检查摘要与当前章，不再次加载旧备份。
- 回忆录保留必要选择、关键里程碑与结果；旧完整输入通过原备份保留，不嵌套到每一份新存档。

## 7. 已实施与同机实测（2026-10-14）

`CompletedChapterSummary`只归约已完成事务，`BoundedSaveCodec`负责严格字段、连续归档、当前章原控制器重放与导航检查。`CampaignState`的旧版导出/校验保留独立入口；实际SaveStore读/写使用v4。只有原子写盘成功才采用压缩后的候选会话，失败不替换内存。备份同名但内容不同会阻止覆盖。
