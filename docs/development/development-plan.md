### 统一注册规则

- 已有 `SC-xx-xx`、`MQ-xx`、`Bxx`、`PZ-xx`、`MEM_*` 保留为策划源ID。运行场景/地图/动作采用稳定snake_case语义ID，设显式映射，不修改源文档来迁就文件名。
- 映射记录至少含 `runtime_id`、`resource_type`、`source_document`、`source_id`、`chapter`、`quest_step`、`asset_path`、`status`、`decision_note`；一场戏可跨地图，一个地图可承载多场戏。
- 02的 `MAP-01-A` 为神仙度；08的 `MAP-01` A/B却是钓鱼城瓮城/弩台。06又使用MG编号；**绝不能把相同原始编号自动当成同一资产**。使用文档命名空间识别，例如 `script02:MAP-01-A` 与 `art08:MAP-01-A`。
- ACT编号同样必须加来源命名空间，按角色、语义、朝向、场次核对，不能仅字符串相等就绑定。例：05的ACT-03为晓霜递卷，08同号为梁萧伸手。
- 添加编译前检查：全局runtime ID唯一、引用可解析、每个运行场景有来源、必需角色在场、技能已授予、目标有终态、奖励事务唯一、资源文件存在。
- 06存档说明残留40级，按现行07和规则JSON的80级执行；阶段限定角色固定面板不能按核心成长公式二次换算。

## 4. 共用系统与资源流水线

### 4.1 叙事与内容

任务状态与演出解耦。七阶段为 UNDISCOVERED、ACCEPTED、INVESTIGATING、LOCAL_CHOICE、COOP_EXECUTING、AFTERMATH_TALK、ARCHIVED_ECHO。选择分即时回应、延迟回响、方法差异；不添加恋爱好感分或改写不可逆生死。每章维护场次→任务步骤→地图→台词→动作→音效→战斗/机关清单。

演出使用可幂等提交的终态事务，统一处理坐标/输入、队伍、物品、奖励、记事、地图状态。正常播放、快进、读档和重试必须一致。重大余波可静默入账，禁止升级/掉落浮窗破坏演出。

### 4.2 战斗

纯规则层与视觉/音频分开；数值来自已统一的数据，不直接把审阅CSV复制成正式运行配置。先落实行动准备阶段、速度轴、伤害路由、状态、冷却、破招/韧性、MP、协力和非致命规则，再加入各章敌AI和目标判定。

首领按实际目标配平；护送、封功、破器、生存不等于击空总HP。所有战中试用技能在选招前授权，胜利固化，重试恢复一致快照。不得让未解锁技能成为必需解法。

### 4.3 机关与场景

8类PZ逐一做输入、目标、重置、三层渐进提示、成功事务、退出/再入与存档测试。探索支持四向动画和归一化斜向移动；世界320×180、32×32瓦片、最近邻整数缩放；角色脚底碰撞和Y排序。

### 4.4 手工像素与音频

按08的体型、色板、容器和锚点制作手工像素资源；程序占位绘制须显式标为临时，不伪称手工终稿。禁止把生成式概念图、直接缩图或未经修正的左右镜像作为最终像素资产。`assets/concepts`只作视觉参考。

资源导入依次经过：ID对齐→地图面积预算→角色/姿态草图→逐帧像素制作→碰撞/锚点/图集→引擎预览→色板/尺寸检查→实机演出验收。按资源类型校验锚点，标准人(16,44)、魁梧(24,44)、大型(32,58)，禁止统一强制(16,44)。

UI/中文字幕独立高清渲染，像素世界不得随UI抗锯齿模糊。08底部48px安全带与02的42px存在差异，先采用更保守48px并记录，需实机检查重要动作不被遮挡。配音预算与演员表是计划，不表示已有录音或制作授权；静音占位应可识别，不能阻塞基础系统验证。

## 5. 已收口与待收口问题

### 当前combat_rules_v1已经处理，禁止回退

- 低速护卫先于速度轴准备，原始伤害分流后各分支防御结算一次；不连锁援护，AOE自身包不重复。
- T轮使用CD=c，T+c+1再用；破招当轮不重复，韧性从下一轮开始，易伤到T+1末。
- 协力容量3、合招预留2、每轮普通收益最多1；取消只退一次，不凭退款刷协力。
- 战斗开场满MP，多阶段不重置；每人每轮回气上限12，取消战后MP奖励。
- 非致命B11覆盖全部伤害渠道；CO01/04/05战中试用、胜利固化及其余授予节点明确。
- 80级成长与XP账、首领入场XP检查点、关卡固定K、减伤/护盾/回复上限、持续伤害首领上限已统一。
- B03逃脱、B12封功、B15阶段目标、B16护送/破器进度与相关出战阵容已补齐。

现有审阅记录184项检查通过仅覆盖静态和有限参考场景；实现后需重新执行并补引擎与完整战斗测试。

### 尚不能视为已解决

- 地图MG/MAP、ACT及台词/场次绑定冲突；28组主地图面积较原预算超约70.4%。规划中的“100%达标”不是资源实装证明。
- 人物设定校勘：了情身份、中条五宝姓名、阿莫/朱雀、天香第二局对手、萧千绝终局收徒对象。先复核来源，重大改编决定不能静默处理。
- 06存档等级残留40、对白安全区42/48、部分中卷镜头1.15x推进与固定像素整数缩放冲突。镜头应优先保清晰、通过平移/站位表现，例外须记录。
- 序章场次/任务差异、全作时长估计差异、敌AI完整轮换、真实胜率/回合数与情绪节奏均需试玩。

```sh
python game/tools/validate_data.py
mkdir -p /tmp/kunlun-cache /tmp/kunlun-test-data /tmp/kunlun-config
export XDG_CACHE_HOME=/tmp/kunlun-cache
export XDG_DATA_HOME=/tmp/kunlun-test-data
export XDG_CONFIG_HOME=/tmp/kunlun-config
godot --headless --path game --editor --import --quit
godot --headless --path game --script res://tests/run_tests.gd
godot --headless --path game --quit-after 120
```

先import再运行测试；Godot部分脚本解析错误可能仍退出0，必须同时扫描日志中的 `SCRIPT ERROR` / `ERROR`。图形启动命令为 `godot --path game`，受限云机也须设置可写XDG目录。使用独立测试数据目录避免影响个人存档。
