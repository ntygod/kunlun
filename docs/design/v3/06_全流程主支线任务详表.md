## 第一部分：任务状态机与叙事耦合规范

### 1.1 叙事驱动的任务设计总纲

《昆仑》的任务系统摒弃传统网游式“头顶感叹号接取—击杀N只怪物—交回换取数值奖励”的工业流水线套路，确立**以人物处境与生命记忆为轴心**的单机叙事任务范式：

1. **主线即人生因果链（Single-Spine Causal Chain）**
   全作由序章加20章共21个主线任务单元（`MQ-00` 至 `MQ-20`）严密咬合而成。玩家在主线中经历的每一次修屋、算题、断桥、分水、放闸，皆直接对应梁萧从“孤傲执拗、算无遗策却刚愎自用”到“直面创痛、知止守柔、慨然殿后”的四重人生蜕变，以及花晓霜、柳莺莺、花生、阿雪、风怜各自独立的生命抉择。
2. **支线即岁月肌理（Living Texture Side-Quests）**
   全作严格控制为16条精选支线（`R01–R08` 人物羁绊、`L01–L06` 地方风物、`K01–K02` 算学格物），总体验时长约8小时，单条体验控制在25～35分钟。每一条支线均不设无意义的跨图折返，而是在当前章节既有的探索动线中，借一册未合的算稿、一只豁口的竹器、一碗分先后端出的温粥、一封未能写完的家书，让玩家亲手触摸同行者与苍生的冷暖。
3. **操作逻辑随心境演化（Mechanic as Character Arc）**
   同一类“调查与破局”交互在不同阶段呈现截然不同的任务指引与操作重心：
   - **少年孤雏期（第01–05章）**：操作偏向“急切拆改、出奇制胜”，调查文本多带少年抢白与争胜心气；
   - **乡居与军旅期（第06–10章）**：华山先问四邻农具与水渠冷暖；入军后一度异化为“按军令核算最大杀伤与破城效率”，直至襄樊火城与常州屠城形成刺痛反差；
   - **医路与鲸海期（第11–15章）**：控制权多次移交花晓霜与柳莺莺，任务交互转向“望闻问切、分水护童、非致命止戈”；
   - **西行与宗师期（第16–20章）**：勘查必先确认“何人受损、如何泄洪护民、如何让人与典籍并存”，拔剑前多一拍沉凝停顿。

### 1.2 主支线任务底层数据结构与 Schema 规范

任务系统在 Godot 4 引擎中实行**任务状态层（Quest State Layer）**与**二维演出层（Cutscene & Performance Layer）**解耦运作：任务层负责阶段推进、条件监听与结算派发；演出层负责固定俯视机位下的精灵走位、手绘肖像切换与结果提交。所有主支线任务统一采用结构化数据表与 JSON 资源驱动，内部管线静态校验工具在编译期自动排查台词漏填、非在场角色发言、退队角色参战、分支缺失终态及重复发奖等异常。

#### （1）任务主表核心字段定义

| 字段名 | 数据类型 | 必填 | 作用域与叙事耦合说明 |
| :--- | :--- | :---: | :--- |
| `quest_id` | `String` | 是 | 全局唯一标识符。主线为 `MQ-00`～`MQ-20`；支线为 `R01`～`R08`、`L01`～`L06`、`K01`～`K02`。 |
| `chapter_window` | `Vector2i` | 是 | 开放章节与截止章节区间 `[open_ch, cutoff_ch]`。踏入不可逆主线锚点前触发温和提醒。 |
| `map_group_ids` | `Array[String]` | 是 | 关联的28组主地图组及子区ID（如 `MG10_HuaShan_Home`），用于舆图路标与8处重访状态图层加载。 |
| `party_roster` | `Dictionary` | 是 | 严格定义本任务在场角色（`present`）、当前操控视角（`controllable`）与剧情支援角色（`support`）。 |
| `knowledge_ledger` | `Dictionary` | 是 | **知情账本**：记录场内各角色当前已知与未知的事实边界（如五龙岭梁萧未知柳莺莺假意周旋之苦心）。 |
| `state_nodes` | `Array[StepNode]` | 是 | 七阶状态机节点序列，包含每一步的目标文本、空间触发器、现场勘查点与完成条件。 |
| `puzzle_binding` | `String` | 否 | 绑定的必经机关或勘查单元ID（`PZ-01`～`PZ-08` 或算学支线单元），含三层渐进提示配置。 |
| `choice_branches` | `Array[ChoiceDef]` | 否 | 局部抉择定义，强制标注类型：`IMMEDIATE`（即时回应）、`DELAYED`（延迟回响）、`METHOD`（方法差异）。 |
| `memory_tags_out` | `Array[String]` | 是 | 结算时写入长期存档的**具名相处记事标签**（如 `MEM_R01_KEEP_DRAFT`），供后续章节检索。 |
| `skip_transaction` | `TransactionDef` | 是 | **快进终态事务包**：当玩家跳过演出时，原子化执行角色坐标、物品增减、队列变更与状态合拢。 |
| `aftermath_walk` | `AftermathConfig` | 否 | **静默余波配置**：定义重大转折后的禁弹窗区间、环境音轨留白、空席站位与信物陈设变化。 |

### 1.3 七阶任务状态机流转规范

每一项主线与支线任务在生命周期内严格遵循下述七阶状态机流转，禁止任何跳步或状态倒灌：

`
[未发现 UNDISCOVERED]
        │ 步入场景视域 / 拾得前置信物 / 主线时序推进
        ▼
[接取 ACCEPTED]
        │ 倾听处境陈述 / 明晰当前阻碍 / 写入任务日志
        ▼
[勘查 INVESTIGATING]
        │ 现场搜证 / 寻访病患或四邻 / 辨识机关机理 (PZ-01~08)
        ▼
[局部抉择 LOCAL_CHOICE]
        │ 即时回应 / 延迟回响 / 方法差异 (选定优先次序或行进方案)
        ▼
[协同执行 COOP_EXECUTING]
        │ 分工协作 / 机关操作 / 短战拆招 / 角色专属指令配合
        ▼
[余波叙话 AFTERMATH_TALK]
        │ 撤出险地 / 围坐分食 / 促膝长谈 / 情感沉淀（禁系统弹窗）
        ▼
[归档回响 ARCHIVED_ECHO]
        │ 写入具名“相处记事” / 移交非功利信物 / 触发后续章节主线台词差异
`

1. **未发现（UNDISCOVERED）**：地图上不显现悬浮感叹号。当操控角色步入特定逻辑区域（如华山村口打谷场），或行囊中持有前置物件（如《大宋江防图》拓片），由环境声景、同伴驻足视线或NPC的劳作自语自然引出。
2. **接取（ACCEPTED）**：触发简短现场对话。对白拒绝“请大侠帮我……事成必有重谢”的市侩口吻，而是由角色的当前生计或危机自然生发；任务界面更新为具体而克制的一句话指引（如“替赵四婶修整漏雨的旧柴棚”）。
3. **勘查（INVESTIGATING）**：玩家操控角色调查现场关键痕迹。若涉及8大必经机关（PZ-01～PZ-08），此阶段激活三层渐进提示的第一层“表象观察”；若涉及同伴，同伴会主动走至破损处驻足观察，提示潜在隐患。
4. **局部抉择（LOCAL_CHOICE）**：在关键分歧点提供二至三个具体行动方案。抉择界面不附带任何“善／恶”标签或好感度数值浮动预览，纯粹呈现角色当下的行动侧重（如“先修水车”还是“先修推车”，“保留草稿”还是“撕去重来”）。
5. **协同执行（COOP_EXECUTING）**：执行既定方案。同伴依据抉择自主承担另一半职责（如梁萧削竹破篾，阿雪生火煮茶并清理刨花）；涉及首领战或特殊遭遇战时，严格匹配剧情在场人员与专属指令机制。
6. **余波叙话（AFTERMATH_TALK）**：危难化解或劳作完工后，强制进入无操作打断的余波阶段。角色坐下歇息、端起热粥或并肩凭栏；对白围绕方才的经历自然吐露心声，界面隐藏全部战利品与经验值弹窗。
7. **归档回响（ARCHIVED_ECHO）**：任务从活跃列表移入“往事记事”，写入唯一的具名羁绊标签；获得的报酬为具名生活信物（如“豁口的粗瓷茶碗”、“编好的柳笠”）或被动心性特性，并在后续一至两章的主线对白或场景陈设中触发可见回响。

### 1.4 局部抉择三分类矩阵与设计约束

本作摒弃虚假的“道德善恶条”与影响世界走向的平行多结局分支，全作维持原著单一正史终局。玩家的一切选择均锚定于**如何在困境中对待身边之人**，分为三类严谨的交互类型：

| 分类 | 定义与实现机制 | 即时表现 | 延迟回响（后续1~2章） | 禁忌边界 |
| :--- | :--- | :--- | :--- | :--- |
| **即时回应<br>(IMMEDIATE)** | 对同伴当下陈述的心态反馈，改变对话语气与微动作。 | 触发专属手绘像素动作（如梁萧抢白负手、微微侧头凝听或笨拙伸手扶人）；对方回应台词改变。 | 不改变主线任务目标与道具分布，仅微调次日或下一场景首句闲聊口吻。 | 严禁出现无实质语境差异的纯废话选项；严禁出现崩坏人设的现代网络用语。 |
| **延迟回响<br>(DELAYED)** | 在当面交涉中是否听懂弦外之音、是否坦承昔日过失或是否保留脆弱痕迹。 | 当场对白留白，同伴眼神或站位微调，系统静默写入`MEM_*`标签。 | 在后续主线触发整段差异化叙话；在重访旧地时，地图陈设体现昔日痕迹（如华山檐下竹鸟、江堤旧碑文）。 | 严禁改变原著核心生死走向（如阿雪钱塘之殇、萧玉翎紫竹林之殁不可逆转）。 |
| **方法差异<br>(METHOD)** | 面对具体困局时的资源调配、先后顺序或解题思路。 | 改变任务执行动线、当前场景障碍物移除顺序及同伴分工角色。 | 改变获得的辅助物资构成、解锁不同的双人战术特性；影响NPC对梁萧一行人的处世评价。 | 严禁设计“最优解”以惩罚其他选项；每种解法必须体现不同角色的性格合理性。 |

### 1.5 “相处记事”具名羁绊标签体系与写入规则

系统坚决取缔数字化“好感度 +5”浮窗，将一切同行经历转化为**具名羁绊事件（Memorial Bond Events）**：

1. **原子化持久存档**：羁绊标签以强类型字符串永久写入全局存档结构 SaveData.memorial_bonds，如 MEM_R01_KEEP_DRAFT（保留未合算册）、MEM_MQ08_RANYA_ASTRONOMY（与兰娅算学互信）、MEM_R07_LIU_LEADER_RESPECT（认同柳莺莺为天山主人）。
2. **双人合招前置解锁**：战斗中的双人合招（如梁柳“飞燕掠波·截脉引奇”、梁霜“暗香浮动·水木相生”、霜花“金刚护法·金针度厄”）并非随等级数值自动习得，必须在对应羁绊支线或主线生死共济段落中完成特定相处记事写入方可解锁出战配置。
3. **叙事场景与台词拦截器（Dialogue Interceptor）**：主线剧本引擎在加载每个对话节点前，遍历在场角色的 knowledge_ledger 与已激活的 memorial_bonds。当检测到匹配标签时，自动覆盖通用对白分支，呼出带有前情回忆的专属叙事线。

### 1.6 演出跳过保护、不可逆节点预警与往事回忆录隔离机制

1. **标准化事务流（Skip Transaction Flow）**：当玩家在已看过的过场或多周目选择跳过剧情演出时，系统不使用简单的渐黑淡入，而是执行原子化快进事务包（skip_transaction）：
   - **身位瞬移**：全队角色精准对齐该幕演出的终态像素坐标与朝向；
   - **背包与任务同步**：原子化结算剧情交付的信物、金钱及任务状态推进；
   - **环境图层切换**：门扉开合、火势蔓延、水车修缮等场景Tile图层立即刷新至终态，杜绝图层穿帮与状态脱节。
2. **不可逆主线节点温和预警**：全作共设5处重大地域不可逆跃迁点（第06章从军别华山、第10章逃亡离钱塘、第13章南洋入瀚海、第15章受擒陷百丈、第20章决死守天机）。在踏上不可逆渡口或关卡前，系统在营火或渡船交互处由同伴给出温和语音或台词提醒（如阿雪：“萧哥哥，四邻的活计可都打点妥当了？这一去，不知何时才能再回华山了。”），界面呼出未结支线摘要。
3. **超时支线优雅收拢与往事回忆录隔离**：
   - 若玩家未在开放窗口内完成支线而强行推进主线，该支线不报系统失败红字，而是以优雅笔触转入“未竟之事”札记（如“昔年华山春耕，终因军书急催未能亲手替四邻筑完水车，唯留一段遗憾于心……”）；
   - 通关后解锁主界面的**【往事回忆录】**模式。玩家可在独立存档沙盒中重历错失的16条支线，其探索成果仅供阅览叙事，与正篇史诗通关存档严格物理隔离，杜绝因回溯改写正篇因果。

### 2.2 八大必经机关与勘查单元完整规则表（`PZ-01` 至 `PZ-08`）

全作共设8处主线必经机关或现场勘查单元。每处机关严禁做成脱离剧情的生硬小游戏，全部采用**二维俯视场景实体交互＋图形化算筹面板**双层联动，并统一配备**「表象观察—核心算理—分步演示」**三层渐进提示，玩家可随时按需呼出，也可在故事模式下于第三层提示后直接完成推演。

#### 【`PZ-01`】天机求学：九宫洛书与浑天水枢（所属：`MQ-02` 第02章）
- **机关规则与操作逻辑**：分为寒窗三阶推演。第一阶「天地生成解（洛书九宫）」：拖动1至9枚黑白算筹填入三乘三石盘，使横、竖、斜三向之和皆为十五；第二阶「双手十指题（二进制推演）」：借花晓霜灯下演示的十指屈伸，将0与1的阴阳爻象对应至天机三轮齿槽；第三阶「日变奇算与元外之元」：前九算逐一打通后，第十算「元外之元」棋盘呈现无穷发散的星轨，无论玩家如何拨动算筹均会引发水枢过载，直至触发梁萧呕血掷笔、花晓霜温言劝止的心境收束。
- **三层渐进提示文本**：
  * **第一层（表象观察）**：「石盘中央凹槽刻有五点星纹，四正四隅的铜槽深浅各异——晓霜说过，天机石阵暗合洛书北一南九之位。」
  * **第二层（核心算理）**：「戴九履一，左三右七，二四为肩，六八为足，五居中央。阳数居四正，阴数居四隅，纵横十五方能引动水枢。」
  * **第三层（分步演示）**：「先将五枚白筹嵌入正中中宫；再将上九下北一、左三右七依次落槽，余下偶筹按左上二、右上四、左下八、右下六对角归位。（第十算提示：此题花元茂穷毕生之力亦未能解，放下执念、听晓霜一言方是正途。）」

### 4.2 演出跳过事务（Skip Transaction）回归验证规范

为确保玩家在任何章节跳过剧情动画时不出现数据丢失、身位穿帮或任务卡死，所有主线（`MQ-00`～`MQ-20`）与支线（16条）均配备原子化事务包，回归测试必须通过下述四项硬性检验：

1. **身位与碰撞盒对齐（Transform Alignment）**：跳过演出后，操控角色与同伴精灵严格对齐终态网格（误差0像素），NPC碰撞层与寻路网格动态刷新，杜绝卡入墙体。
2. **信物与行囊事务原子化（Inventory Atomicity）**：剧情交付的信物（如白玉扳指、小柳笠、青杏卷、天罚剑）与消耗品在单帧内完成`Add/Remove`，严禁出现演出跳过后关键钥匙缺失。
3. **队伍阵容与可操作性切换（Roster & Input Lock）**：针对视角切换关卡（如第10章阿雪折返、第13章柳莺莺孤舟主控、第15章晓霜东线、第20章晓霜关闸），跳过演出后立即将输入上下文绑定至正确角色，禁用不可操作角色的行动指令。
4. **场景图层状态无缝切合（Tile Layer Transition）**：涉及火灾、水浸、坍塌或修缮的场景，跳过演出时底层TileMapLayer立即切换至终态图层，粒子特效平滑过渡。

### 4.3 存档字段结构与【往事回忆录】隔离机制

1. **全局存档数据结构定义（SaveData Schema）**：
   - `save_version`: 引擎与数据格式版本号（v3.0）；
   - `chapter_checkpoint`: 当前主线任务阶段ID（如 `MQ20_STEP04_GATE`）；
   - `active_quests`: 活跃任务状态机字典 `{quest_id: state_enum}`；
   - `memorial_bonds`: 已写入的具名相处记事标签列表（`Array[String]`）；
   - `party_status`: 角色历练等级（上限40级）、心性特性槽位配置；
   - `keepsakes`: 独立不可变卖信物列表。
2. **【往事回忆录】物理隔离机制**：
   - 通关后主界面解锁【往事回忆录】。该模式运行于独立的命名空间 `user://memories_sandbox.json`；
   - 玩家可任意回溯体验未能完成的16条支线任务，阅览全套对白与专属演出；
   - 回忆录中的选择与探索结果仅保存在回忆录展示图鉴中，严格禁止写回正篇史诗通关存档（`user://main_story_completed.json`），恪守「人生唯有一途，岁月不可倒流」的武侠沉浸感。
